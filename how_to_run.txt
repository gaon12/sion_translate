HOW TO RUN sion_translate-prepared.zip ON A GPU SERVER
=======================================================

This is the plain-text companion to START-HERE.md.


1. VERIFY AND EXTRACT THE ZIP
-----------------------------

Compare the first command with the SHA-256 supplied by the bundle builder.

sha256sum sion_translate-prepared.zip
python3 -m zipfile -t sion_translate-prepared.zip
unzip sion_translate-prepared.zip
cd sion_translate
python3 scripts/package_gpu_bundle.py verify-tree .

Stop if any command fails. Do not manually patch a failed extraction. Upload the
verified archive again.

The manifest is the authority for the bundle contents. A fully prepared bundle normally
contains the authenticated tokenizer, token features, translation dataset, and foundation
dataset. It retains configured evaluation-only files but excludes raw parallel and
monolingual training corpora, including tracked corpus files. Excluded data, old runs,
checkpoints, virtual environments, and caches must not be present. Manifest format 2 also
binds the exact tracked sion_translate.yaml digest and configured training contract.


2. INSTALL THE PACKAGE AND CHECK CUDA
-------------------------------------

Automatic installation (verifies the bundle first and does not start training):

python3 setup_gpu.py

Internet access and Python venv/ensurepip support are required. If missing on an
Ubuntu/Debian host, install python3-venv first. Use .venv/bin/python afterwards,
or source .venv/bin/activate. The equivalent manual installation follows.

Use the authenticated CPython 3.11/Linux x86_64/CUDA 12.8 dependency lock.
easy_run.py requires exact critical package versions, including Torch 2.10.0+cu128.
An unpinned install or Python 3.12 will fail its runtime preflight.

nvidia-smi
python3 -m pip install "uv==0.12.3"
uv venv --no-config .venv --python cpython@3.11 --managed-python
uv pip sync --no-config requirements/pylock.gpu-cp311-linux-x86_64-cu128.toml --python .venv/bin/python --require-hashes --strict --only-binary :all:
uv pip install --no-config --python .venv/bin/python --no-deps --no-build-isolation --editable .
source .venv/bin/activate

python - <<'PY'
import torch

assert torch.__version__ == "2.10.0+cu128", torch.__version__
assert torch.version.cuda == "12.8", torch.version.cuda
assert torch.cuda.is_available(), "This PyTorch installation has no CUDA support"
print("PyTorch:", torch.__version__)
print("CUDA runtime:", torch.version.cuda)
print("GPUs:", [torch.cuda.get_device_name(i) for i in range(torch.cuda.device_count())])
print("NCCL:", torch.distributed.is_nccl_available())
PY

The lock installs the reviewed Torch build. Keep this environment active for the
remaining commands. NCCL is required when more than one GPU is visible.


3. AUTHENTICATE THE PREPARED INPUTS
-----------------------------------

sion-train --config sion_translate.yaml --prepare-only

A fully prepared bundle should reuse its tokenizer and indexed datasets. Do not continue
if this command reports a graph, tokenizer, token-feature, fingerprint, or inventory
mismatch. A prepared-only bundle cannot rebuild a missing artifact because its raw
training corpora were intentionally omitted; the command fails before allocating a model.
Do not pass --allow-local-checkout here. That option is only for a trusted development
clone without bundle metadata and must not replace this bundle's manifest verification.


4. START OR RESUME TRAINING
---------------------------

easy_run.py reads the authenticated sion_translate.yaml and does not accept --config.
The default now matches configs/modal_80gb.yaml: measured 273M model, foundation
batch 32, SFT 32 x 8 accumulation, and MRT 8 x 2 accumulation capped at 100000 updates.
The MRT update budget takes precedence over its epoch field. This profile targets
one A100/H100 80GB; its runtime estimate does not establish multi-GPU scaling.
The 100k cap is a budget scenario, not a validated quality target. Do not edit the
authenticated configuration in an extracted bundle; rebuild after source changes.

.venv/bin/python easy_run.py

The runner validates the hardware and data, applies the configured architecture,
resumes the furthest authenticated stage, runs optional foundation pretraining,
translation SFT, gold-anchored MRT/preference posttraining, and final verified export.

To disable optional tmux handling:

SION_NO_TMUX=1 .venv/bin/python easy_run.py

These commands target an already provisioned GPU host. The repository's Modal scripts
run bounded diagnostics, not a full training scheduler. Full Modal training additionally
needs persistent checkpoint storage and resumption across execution windows.

Automatic hardware policy:

- Use every visible CUDA GPU.
- Use BF16 only when every rank supports it; otherwise use FP16 automatically.
- Apply the explicit 80GB batch/checkpointing profile and check the smallest visible VRAM.
- Use DDP when full state fits, or FSDP2 when sharding is necessary.
- Keep MRT candidate micro-batches conservative.
- Do not enable torch.compile unless configuration explicitly requests it.


5. OUTPUTS AND RESTARTS
-----------------------

Foundation best:
  runs/modal-80gb/foundation/exports/best
  This is the sion base model and cannot translate.

Translation SFT best:
  runs/modal-80gb/pretrain/exports/best

Final translation best when MRT is enabled:
  runs/modal-80gb/posttrain/exports/best

Resume checkpoints:
  runs/modal-80gb/*/checkpoints/latest

Prepared tokenizer and datasets:
  artifacts/tokenizer
  artifacts/dataset
  artifacts/foundation_dataset

After interruption, run the same command again. The runner resumes only complete,
authenticated checkpoint generations and skips earlier stages when a valid downstream
checkpoint exists.

Before deleting the server, download runs/, artifacts/tokenizer/, the final export
manifest and validation report, the exact configuration, and the environment report.


6. MONITORING AND FAILURE REPORTS
---------------------------------

watch -n 2 nvidia-smi
python3 -m torch.utils.collect_env

Keep the full traceback, nvidia-smi output, collect-env output, Git commit, bundle SHA-256,
configuration, data fingerprint, node/rank count, and final telemetry lines.

See START-HERE.md and docs/H100_TRAINING.md for the complete procedure.
